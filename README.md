# 生活メンテナンス

運動・片付け・自炊などを「毎日」「週○回」の目標で管理する個人用Webアプリです。連続日数ではなく、今週の達成を重視します。サーバー、ビルド、外部フレームワーク、ネット接続は不要です。

## 機能

- 曜日ボタンを1クリックで完了／未完了に切り替え
- 毎日の達成数、週の目標回数、CLEAR表示、全体の目標進捗
- 今日の曜日を枠線と小さな点で表示
- タスクの追加・編集・確認付き削除、メモ、表示順
- 月曜始まりの週表示、前週・次週への移動、今週に戻る
- PC・スマートフォンに対応したダークモード
- 初回のみ4つのサンプル習慣を作成

### Phase 2で追加した機能

- 「習慣を管理」から休止・再開。休止中も編集可能
- 管理画面の↑／↓ボタンで並べ替え。大きな操作領域とキーボード操作に対応
- 「月の振り返り」で実施日数・実施回数・週間目標達成週数を表示
- 前月・次月への移動、今月に戻る
- schemaVersion 1から2への自動移行

テーマ設定・連続記録・ドラッグ＆ドロップは実装していません。

## 起動方法

4つのアプリファイルを同じフォルダーに置き、`index.html` をブラウザーで開いてください。日常利用にはブックマークすると便利です。最新版のChrome・Edge・Firefox・Safariなど、dialog / structuredCloneに対応したブラウザーを使用してください。テストファイルやNode.jsは通常利用には必要ありません。

## 休止・再開と表示順

タスクの `periods` に有効期間を保存します。各期間は `{ start: "YYYY-MM-DD", end: null }` のような形で、開始日を含み、終了日を含みません。開いている期間があれば実行中、なければ休止中です。別の状態booleanを重複して持たず、有効期間から状態を判定します。

- 新しい習慣は追加した日から有効です。開始前の日にはチェックできません。
- 休止は操作した当日から反映され、通常の今週画面から非表示になります。
- 再開は操作した当日から反映されます。別日の再開は新しい有効期間を追加します。
- 同じ日に休止・再開した場合は期間をまとめ、不要な期間を増やしません。
- 過去週は、その週に1日以上有効だったタスク、またはチェックのあるタスクを表示します。有効日のチェックは変更でき、開始前・休止期間のチェックは読み取り専用です。
- 休止以前・休止当日・将来の日付も含め、既存のチェックを削除しません。記録が休止期間内に残っていても実施数には含めます。そのため実施数が有効日数を超える場合があります。
- 「毎日」の週目標は、その週の有効日数です。全週有効なら従来どおり7日です。「週○回」の目標回数は一部休止の週も変更しません。
- 「削除」は確認付きで行い、管理一覧から外れて再開できません。チェックのある週には読み取り専用の履歴が残ります。月ビューにも実施記録のある月（週○回ではその月に割り当てられた週に記録がある場合も）を残します。

並べ替えは休止中の習慣も含む一覧で行います。↑／↓操作後は表示順を連番にして保存するため、旧データに同じ順序値があっても確実に移動できます。休止・再開では表示順を変更しません。編集画面で数値を直接変更する従来の操作も引き続き使用できます。同じ値の場合は保存されている配列の順序で表示します。

## 月次集計ルール

1. **実施日数・回数**：チェックの実際の日付が属する月に集計します。1タスクにつき1日に1回です。有効期間外に保持されたチェックも含めます。
2. **毎日の分母**：その月の有効日数です。全月有効なら月の日数、開始前・休止期間があればその日数を除きます。
3. **週間目標達成の所属月**：その週の月曜日が属する月へ集計します。判定には月境界にかかわらず月曜〜日曜の全チェックを使用します。
4. **週○回の分母**：月曜日がその月にあり、週内に1日以上有効だった週の数です。一部だけ有効な週も1週として数え、目標回数は変更しません。全週休止・開始前の週は除きます。
5. 表示は月全体を対象とします。今月・未来の月も、有効期間が続く場合は今後の日・週を分母に含めます。途中の週や月では値が更新されるため、確定結果を意味しません。

例：2026/9/28（月）〜10/4（日）の週は、週間CLEARを9月に集計します。10/1のチェックそのものは10月の実施回数です。2026/10/26（月）〜11/1（日）のCLEARは10月に入り、11/1のチェックは11月の実施回数に入ります。年境界も同じルールです。月によって週間目標の分母は4週または5週になり、有効期間によってさらに減ります。

目標・種類・名前の編集は過去の表示と集計にも反映されます。チェック履歴と有効期間はそのまま保ちます。目標設定そのものの変更履歴は今回追加していません。

## データ保存とmigration

localStorageの `life-maintenance` キーに、`schemaVersion: 2`、`tasks`、`records`、`settings` をJSON形式で保存します。チェック履歴はタスクIDと `YYYY-MM-DD` のローカル日付で管理します。UTC文字列への変換は行いません。週の開始日は月曜日です。

schemaVersion 1のデータは起動時に検証して複製し、各タスクに `periods` を追加してからschemaVersion 2として保存します。

- ID・名前・メモ・種類・目標回数・表示順・削除状態・チェック履歴・設定を保持します。
- 旧データでは開始日が分からないため、`start: null` を「以前から有効」と扱います。過去の週や記録のない日も、従来と同じように確認できます。
- 旧データの削除済みタスクは削除日も不明なため、移行日を有効期間の終了日とします。実際の削除日を復元したものではありません。
- すでにversion 2なら検証のみ行い、期間を追加しません。複数回起動・移行関数実行しても期間や履歴は増減しません。
- 移行後の保存に失敗した場合は旧データが残り、変更操作を無効化して通知します。不正データや未対応バージョンも上書きしません。

リロードしてもデータと並び順は残ります。起動時は常に今週を表示します。

**localStorageを消すとデータも消えます。** ブラウザーやプロファイルごとに保存先は異なり、端末間の同期はありません。プライベートブラウジングでは終了時に失われる場合があります。ファイルを移動した場合の保存先やfile URLでのlocalStorageの動作はブラウザーに依存するため、同じブラウザーで同じ場所から開いてください。

通常操作でも保存に失敗した場合は通知し、画面上の変更を確定しません。

## 確認結果

Edgeの独立したテスト用ブラウザーで58項目の自動検証を実施しました。

- 初回起動、チェックON/OFF、毎日7/7、週目標のCLEAR・超過・解除
- 前週・次週、月境界の週、年境界の週
- 追加・編集・削除・削除キャンセル、削除済み履歴、リロード後の保持
- 休止・同日の再開・別日の再開、チェック履歴の完全保持、過去週表示、有効期間外の操作制限
- 同じ順序値を持つ旧タスクの並べ替え、休止中の並べ替え、再開後・リロード後の順序
- 月表示、前月・次月、年境界、実施日の所属月と月曜日の所属月、休止日を除いた分母
- 旧データの完全保持、schemaVersion 2への移行、繰り返し移行、未対応・不正データ保護、移行時の保存失敗
- 日本と米国のタイムゾーン、JavaScriptエラーがないこと
- PC幅1200pxとスマートフォン幅375pxの画面・管理ダイアログを目視確認、横方向のはみ出し検査

開発者向けの再確認は、Node.jsとPlaywrightを利用できる環境で `node tests/verify.cjs` を実行します。既定ではインストール済みEdgeを使い、`TEST_BROWSER` 環境変数でPlaywrightのブラウザーチャンネルを指定できます。テストは独立した一時プロファイルを使い、実際の利用データを操作しません。確認画像は `tests/` に出力します。
